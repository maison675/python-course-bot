# Модель памяти Python — от 0 до 100%

Добро пожаловать в продвинутый трек. Здесь мы перестаём учиться синтаксису и начинаем разбираться, **как Python реально работает**. Это нужно если ты хочешь:
- проходить серьёзные собеседования (Yandex, Avito, Сбер, FAANG);
- оптимизировать код в проде;
- понимать сообщения об ошибках на уровне «почему именно так»;
- читать исходники CPython и стандартной библиотеки.

Первая тема — модель памяти. Это фундамент всего остального: GIL, GC, дескрипторов, asyncio. Если ты не понимаешь, что такое **ссылка** в Python — ты в любом сложном коде будешь натыкаться на «магические» баги.

---

## 1. Всё в Python — объекты

Начнём с центрального тезиса: **в Python всё — объект**. Числа, строки, функции, модули, классы, исключения — всё. У каждого объекта есть три неизменных свойства:

1. **id** — уникальный идентификатор (адрес в памяти в CPython).
2. **type** — класс объекта.
3. **value** — содержимое (для immutable — фиксировано; для mutable — может меняться).

```python
x = 42
print(id(x))      # 9789...984 — адрес
print(type(x))    # <class 'int'>
print(x)           # 42
```

Объекты живут в куче (heap). Переменные — это **имена**, привязанные к объектам. Это первое что нужно понять до конца.

---

## 2. Переменные — это имена, не «коробки»

В C/C++ переменная — это «коробка», в которой лежит значение. `int x = 5` — это «зарезервируй 4 байта, положи туда 5».

В Python всё иначе. `x = 5` означает:
1. В куче создаётся (или находится — для маленьких int) объект «5».
2. Имя `x` привязывается к этому объекту.

```
       x ───────► [int: 5]
```

Когда ты пишешь `y = x`, имя `y` привязывается к **тому же объекту**, не копируется значение:
```
       x ───┐
            ├──► [int: 5]
       y ───┘
```

```python
x = 5
y = x
print(id(x) == id(y))    # True — один объект
print(x is y)            # True — то же самое
```

Когда ты пишешь `x = 6`:
```
       x ───────► [int: 6]
       y ───────► [int: 5]    (y не изменилось!)
```

`x = 6` **не модифицирует** объект «5», а просто перепривязывает имя `x` к новому объекту «6». Объект 5 остался — `y` всё ещё на него ссылается.

---

## 3. Mutable vs immutable — последствия

### Immutable: int, float, str, tuple, frozenset, bytes

Эти объекты **нельзя изменить**. Любая «модификация» — это создание **нового** объекта.

```python
s = "hello"
s += "!"      # создан новый объект "hello!", s перепривязано
```

Поэтому когда у тебя есть несколько имён, указывающих на immutable — изменение одного не влияет на других:
```python
a = "abc"
b = a
a = "xyz"     # a теперь на новый объект, b всё ещё на "abc"
print(b)      # 'abc'
```

### Mutable: list, dict, set, и большинство классов

Эти объекты **можно изменить** на месте. Если несколько имён указывают на один mutable — изменение через одно имя видно через все:
```python
a = [1, 2, 3]
b = a
a.append(4)
print(b)      # [1, 2, 3, 4] — !!! те же данные
print(a is b) # True
```

Это «псевдоним» (alias), и это причина 80% багов начинающих.

### `+=` — для mutable и immutable работает по-разному

```python
# immutable:
a = (1, 2)
b = a
a += (3,)        # __iadd__ не определён → __add__ → новый объект
print(b)         # (1, 2) — независимо

# mutable:
a = [1, 2]
b = a
a += [3]         # __iadd__ → мутация на месте
print(b)         # [1, 2, 3] — !!!
```

Запомни: для mutable `+=` это `extend`, для immutable — это `=` плюс новый объект.

## 4. id() и оператор `is`

`id(obj)` — возвращает уникальный идентификатор. В CPython это адрес в памяти. Между разными объектами id всегда различается.

`a is b` — сравнение идентичности: возвращает True если **тот же объект** (`id(a) == id(b)`), False иначе.

```python
a = [1, 2]
b = a
c = [1, 2]

print(a is b)      # True — то же самое
print(a is c)      # False — разные объекты, хотя содержимое равно
print(a == c)      # True — содержимое равно
```

### Когда использовать `is`

**Только** для трёх случаев (и их аналогов):
- `x is None` / `x is not None`
- `x is True` / `x is False`
- проверка «тот же ли это объект» в специфических случаях

```python
if x is None:        # ✅
if x == None:        # ⚠️ работает, но плохо
```

Для **значений** — `==`. `is` не гарантирует ничего про значения, только про идентичность объектов.

## 5. Маленькие int кэшируются — Small Integer Cache

CPython предзагружает объекты для int от **-5 до 256**. Поэтому:
```python
a = 5
b = 5
print(a is b)    # True — один и тот же объект из кэша

a = 1000
b = 1000
print(a is b)    # False (обычно) — разные объекты
```

⚠️ Это **деталь реализации**, не свойство языка. В REPL результат может отличаться от скрипта (REPL делает оптимизацию, объединяя одинаковые литералы в одной строке кода).

**Никогда не полагайся на `is` для сравнения int**. Только `==`.

## 6. Строки и интернирование

Короткие строки (имена-подобные, длина ≤ ~20, состоят из букв/цифр/_) автоматически **интернируются** — кэшируются и переиспользуются:

```python
a = "hello"
b = "hello"
print(a is b)    # True — обычно интернировано

a = "hello world!"
b = "hello world!"
print(a is b)    # может быть True, может False — зависит от версии Python
```

### Принудительное интернирование

```python
import sys
a = sys.intern("some long string")
b = sys.intern("some long string")
print(a is b)    # True
```

Используется для оптимизации памяти когда у тебя миллион одинаковых строк (например, имена ключей в большом наборе словарей).

## 7. Reference counting — основной механизм GC

CPython использует **подсчёт ссылок** для управления памятью. Каждый объект знает, **сколько имён** на него указывают:

```python
import sys

a = [1, 2, 3]
print(sys.getrefcount(a))    # 2 — само a + временная ссылка для getrefcount

b = a
print(sys.getrefcount(a))    # 3 — теперь и a, и b

del b
print(sys.getrefcount(a))    # 2 — снова

del a    # счётчик становится 0 → объект освобождается мгновенно
```

Когда счётчик ссылок объекта становится 0 — память **сразу** освобождается. Это и есть «детерминированный GC».

### Преимущества refcount

- сразу же освобождает память;
- предсказуем (не пауз GC);
- хорошо работает с RAII (контекстные менеджеры).

### Недостатки

- **циклы**: если `a → b → a`, никто не дойдёт до 0:
```python
a = []
b = []
a.append(b)
b.append(a)
del a
del b
# счётчик не 0 — есть циклическая ссылка через списки
```

Для разрыва циклов есть **второй слой GC** — generational garbage collector. Раз в N аллокаций он находит и освобождает циклы. Подробно — в теме 18 (CPython под капотом).

## 8. Аллокаторы CPython

CPython не делает напрямую `malloc()` для каждого мелкого объекта (это было бы катастрофически медленно). Вместо этого:

### Уровни аллокатора

1. **Object-specific allocators** — для часто используемых типов (int, list, dict). Например, free-list для int.
2. **PyMalloc** — Python's small object allocator. Аллоцирует объекты ≤ 512 байт. Использует **арены** (256 КБ блоки), разбитые на пулы (4 КБ), разбитые на блоки нужного размера.
3. **`malloc` системы** — для крупных объектов (> 512 байт).

### Free lists

Для int, frame, list и нескольких других — у Python есть **free list**: когда объект освобождается, его не возвращают системе, а кладут в список свободных. Следующая аллокация — из этого списка, без syscall.

```python
import sys
# создаём и удаляем int много раз — почти бесплатно благодаря free list
for _ in range(1_000_000):
    x = 42
```

Это объясняет, почему `int(x)` в Python такой быстрый, несмотря на то что объект int — это «хип-аллоцированный» int.

## 9. Размеры объектов

```python
import sys

sys.getsizeof(0)            # 28 — int
sys.getsizeof(2**100)       # 44 — большой int
sys.getsizeof("")            # 49
sys.getsizeof("a")           # 50
sys.getsizeof("привет")     # 86
sys.getsizeof([])            # 56
sys.getsizeof([1, 2, 3])     # 80
sys.getsizeof({})            # 64
sys.getsizeof({"a": 1})      # 232
sys.getsizeof(set())         # 216
```

В Python объекты **намного больше** чем «голые» данные. int — 28 байт (хотя «настоящих» — 4-8). Список из 3 элементов — 80 байт (хотя 3 указателя — 24).

Заголовок объекта содержит:
- `ob_refcnt` (8 байт) — счётчик ссылок
- `ob_type` (8 байт) — указатель на тип
- (для контейнеров) `ob_size` (8 байт) — размер

Поэтому Python — не язык для miniature memory footprint. Если миллионы объектов — рассмотри `__slots__`, `array`, `numpy`, или вообще не Python.

### `getsizeof` не считает рекурсивно

```python
sys.getsizeof([1, 2, 3])    # 80 — но это БЕЗ размера элементов
```

Каждый элемент — отдельный int. Чтобы посчитать всё:
```python
def total_size(obj, seen=None):
    if seen is None:
        seen = set()
    if id(obj) in seen:
        return 0
    seen.add(id(obj))
    size = sys.getsizeof(obj)
    if isinstance(obj, dict):
        size += sum(total_size(k, seen) + total_size(v, seen) for k, v in obj.items())
    elif hasattr(obj, '__iter__') and not isinstance(obj, (str, bytes)):
        size += sum(total_size(x, seen) for x in obj)
    return size
```

Или используй `pympler.asizeof` для серьёзного анализа.

## 10. Пример: почему `pass-by-reference` нет в Python

В Python — **pass-by-sharing** (передача по совместному использованию). Параметр функции — это новое имя, привязанное к тому же объекту.

```python
def modify(lst):
    lst.append(99)         # мутирует, видно снаружи

def reassign(lst):
    lst = [1, 2, 3]        # перепривязывает локальное имя, не видно

a = [1, 2]
modify(a)
print(a)      # [1, 2, 99]

a = [1, 2]
reassign(a)
print(a)      # [1, 2] — не изменилось
```

Это можно вывести из того, что мы знаем:
- `modify` мутирует через `lst.append` — мутация видна везде.
- `reassign` делает `lst = ...` — перепривязка локального имени, не влияет на внешнее `a`.

Это и есть pass-by-sharing.

## 11. globals(), locals(), vars()

Python хранит области видимости в виде словарей. Можно их получить:

```python
x = 10

def f():
    y = 20
    print(globals())   # переменные модуля
    print(locals())    # переменные функции
    print(vars())      # синоним locals() в локальном контексте

f()
```

Это объясняет почему имена в Python такие гибкие. Всё — словарь.

`globals()` модифицируем — можно создать переменную:
```python
globals()["new_var"] = 42
print(new_var)         # 42
```

В функциях `locals()` обычно **только для чтения** (изменения не пробрасываются обратно).

## 12. Жизненный цикл объекта

```python
x = MyClass()        # __new__, __init__
del x                # счётчик → 0 → __del__, память освобождается
```

### `__del__` — финализатор

```python
class Resource:
    def __del__(self):
        print("Освобождаю ресурс")

r = Resource()
del r                # 'Освобождаю ресурс'
```

⚠️ `__del__` вызывается при освобождении, но:
- **не гарантировано вообще** — при выходе программы Python может не вызвать;
- порядок при циклических ссылках непредсказуем;
- исключения внутри `__del__` молча игнорируются.

Для надёжной очистки — **контекстные менеджеры** (`__enter__`/`__exit__`), не `__del__`.

## 13. weakref — слабые ссылки

Иногда хочешь ссылаться на объект, но не мешать его удалению:

```python
import weakref

class Foo:
    pass

f = Foo()
ref = weakref.ref(f)
print(ref())          # <Foo object>

del f
print(ref())          # None — объект исчез, ссылка «ослабла»
```

Используется для:
- кэшей (объект может быть удалён, кэш об этом узнает);
- наблюдателей;
- разрыва циклов (родитель → ребёнок strong, ребёнок → родитель weak).

`weakref.WeakValueDictionary`, `weakref.WeakKeyDictionary` — словари со слабыми ссылками.

## 14. Структура объекта в памяти (CPython)

Чтобы понять до конца, посмотрим в исходник CPython. Объект в памяти выглядит так (упрощённо):

```c
struct PyObject {
    Py_ssize_t ob_refcnt;        // счётчик ссылок
    PyTypeObject *ob_type;        // указатель на тип
    // ... данные конкретного типа
};
```

Для int:
```c
struct PyLongObject {
    PyObject base;                // refcnt + type
    Py_ssize_t ob_size;           // знак + длина в digit-ах
    digit ob_digit[1];            // VLA с цифрами
};
```

Для list:
```c
struct PyListObject {
    PyObject_VAR_HEAD              // refcnt + type + size
    PyObject **ob_item;             // массив указателей
    Py_ssize_t allocated;           // capacity
};
```

Это объясняет:
- почему list занимает много памяти (заголовок + указатели + сами объекты);
- почему `lst[i]` — O(1) (индексация в массиве);
- почему `append` амортизированно O(1) (с запасом по capacity).

## 15. Утечки памяти

«Настоящих» утечек в Python почти нет (refcount + GC), но есть **псевдо-утечки**:

### Глобальные кэши

```python
cache = {}

def f(x):
    if x not in cache:
        cache[x] = expensive(x)
    return cache[x]
```

Кэш растёт неограниченно. Решение — `lru_cache` с `maxsize` или `WeakValueDictionary`.

### Циклы с `__del__`

```python
class A:
    def __del__(self):
        ...

a = A()
a.self = a    # цикл
del a
# в Python 3.4+ освобождается через цикл-GC
# раньше 3.4 — мог не освобождаться никогда
```

### Кэш в декораторе

```python
@lru_cache(maxsize=None)         # ⚠️ неограниченно
def f(x):
    ...

# Лучше:
@lru_cache(maxsize=1000)
```

### Замыкания, удерживающие большие объекты

```python
def make():
    big_data = load_huge_data()
    def inner():
        return len(big_data)
    return inner

f = make()        # big_data удерживается через замыкание навсегда
```

## 16. Профилирование памяти

```python
import tracemalloc

tracemalloc.start()
# ... код
snapshot = tracemalloc.take_snapshot()
top = snapshot.statistics("lineno")
for stat in top[:10]:
    print(stat)
```

Альтернативы:
- `memory_profiler` — построчный профиль памяти.
- `pympler` — для глубокого анализа.
- `objgraph` — визуализация графа объектов.

## 17. Что нужно запомнить

- В Python всё — объект, у каждого id, type, value.
- Переменные — это имена, привязанные к объектам, а не «коробки».
- `=` — перепривязка, не копирование.
- Mutable объекты можно изменить «на месте» через все ссылки на них.
- `is` сравнивает идентичность (id), `==` — значения. Используй `is` только для None, True, False.
- Маленькие int (-5..256) и короткие строки кэшируются — но не полагайся на это.
- Reference counting + cyclic GC — двухслойный сбор мусора.
- CPython аллоцирует мелкие объекты через PyMalloc (арены/пулы/блоки).
- Объекты в Python **большие** — int 28 байт, list начинается с 56.
- `__del__` — не гарантирован; для надёжной очистки — контекстные менеджеры.
- `weakref` для ссылок «без удержания».
- Для глубокого анализа памяти — `tracemalloc`, `pympler`, `objgraph`.

После этой темы ты понимаешь, что происходит «под капотом» при каждом присваивании. Дальше — детали реализации CPython: байткод, компиляция, исполнение.
