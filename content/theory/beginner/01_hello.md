Эта тема — про то, как в Python вообще что-то выводится на экран. Кажется простой, но за `print('Hello')` стоит огромная цепочка: от вызова функции до пикселей в терминале. Если ты её поймёшь — дальше всё пойдёт как по маслу.

📑 Что разберём:
1. Что такое `print` и какая у него сигнатура.
2. Что происходит, когда ты вызываешь `print('Hello')` — пошагово.
3. Аргументы `sep`, `end`, `file`, `flush` — все четыре, с примерами.
4. Эскейп-последовательности: `\n`, `\t`, `\r`, и другие, о которых обычно не рассказывают.
5. Сырые (raw) строки — `r"..."`.
6. Кодировки и Unicode: почему ты иногда видишь крякозябры.
7. `print` vs `sys.stdout.write` — в чём разница.
8. ANSI-цвета в терминале.
9. Типичные ошибки и их причины.
10. Что внутри: как CPython это реализует.

📌 *1. `print` — это не команда, а функция*

В Python 2 `print` был оператором: писали `print 'Hello'` без скобок. С Python 3 (PEP 3105) `print` стал обычной встроенной функцией, как `len` или `abs`. Это значит, что её можно:
- передать как аргумент (`some_func(print)`),
- сохранить в переменную (`p = print; p('hi')`),
- переопределить (`builtins.print = my_print`),
- подсмотреть сигнатуру через `help(print)`.

Полная сигнатура:

```
print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)
```

`*objects` — любое количество позиционных аргументов: чисел, строк, объектов. `sep`, `end`, `file`, `flush` — keyword-only, передаются по имени.

═══════════════════════════════════════

📌 *2. Что происходит, когда ты пишешь `print('Hello, World!')`*

Цепочка действий — пошагово:

1. *Парсинг.* Питон видит идентификатор `print` и пару скобок — это вызов функции.
2. *Lookup.* Имя `print` ищется по правилу LEGB: сначала локальная область, потом замыкания, модуль, наконец `builtins`. Находит функцию `builtins.print`.
3. *Вызов.* В функцию приходит один объект — строка `'Hello, World!'`.
4. *Преобразование.* Для каждого объекта вызывается `str(obj)`. У строки это сама строка.
5. *Сборка.* Между объектами вставляется `sep`, в конце — `end`. Получается итоговая строка.
6. *Запись.* Готовая строка передаётся в `file.write(...)`. По умолчанию `file = sys.stdout`.
7. *Буферизация.* `sys.stdout` — текстовый поток с буфером. Если буфер заполнился или встретился `\n` (в терминале), данные уходят в ОС. Если `flush=True` — буфер сбрасывается принудительно.
8. *Системный вызов.* ОС получает байты, пишет их в дескриптор (обычно 1 = stdout), терминал их рисует.

Главное: `print` сам по себе ничего не «печатает» — он просто формирует строку и отдаёт её потоку. Дальше всё зависит от потока (файл, стандартный вывод, `StringIO`).

═══════════════════════════════════════

📌 *3. Аргументы `sep` и `end`*

Когда передаёшь несколько объектов, `print` объединяет их через `sep` (по умолчанию пробел) и в конце добавляет `end` (по умолчанию `\n`).

```python
print('a', 'b', 'c')         # a b c
print('a', 'b', 'c', sep='-') # a-b-c
print('a', 'b', 'c', sep='') # abc
print('a', 'b', 'c', sep='\n') # a, b, c на разных строках
```

`end` управляет тем, что идёт *после* всего вывода:

```python
print('Hello', end='')      # без перевода строки!
print(', World!')           # пишется на той же строке
# Итог: Hello, World!\n
```

Это очень полезно для прогресс-баров (`end='\r'` — возврат в начало строки) и для вывода без новой строки в конце.

⚠️ Не путай `sep` и сложение строк:

```python
print('a', 'b')        # 'a b'  — два аргумента, sep=' '
print('a' + 'b')       # 'ab'   — один аргумент, склеенный сложением
```

📌 *4. Аргумент `file`*

По умолчанию `print` пишет в `sys.stdout` — стандартный поток вывода. Но можно перенаправить куда угодно, лишь бы у объекта был метод `.write(str)`.

📍 Запись в файл:

```python
with open('log.txt', 'w', encoding='utf-8') as f:
    print('Привет, файл!', file=f)
```

📍 Запись в stderr (стандартный поток ошибок):

```python
import sys
print('Что-то пошло не так', file=sys.stderr)
```

`stderr` существует отдельно от `stdout`, чтобы:
- логи и ошибки не смешивались с обычным выводом;
- их можно было перенаправить отдельно: `python script.py > out.log 2> err.log`;
- в терминале они показываются сразу (stderr не буферизуется построчно).

📍 «Поймать» вывод в строку (часто используют для тестов):

```python
import io
buf = io.StringIO()
print('hello', file=buf)
text = buf.getvalue()  # 'hello\n'
```

📌 *5. Аргумент `flush` и буферизация*

Чтобы понять `flush`, надо знать про *буферизацию*. Запись в файл/терминал — дорогая операция (системный вызов ядра). Поэтому Python копит данные в буфере и отправляет их пачками:

- *Block buffering* — выдаём по куску в N байт. Используется при пайпинге (`python script.py | grep ...`).
- *Line buffering* — выдаём после каждого `\n`. Используется в интерактивном терминале.
- *No buffering* — каждый `write` идёт сразу. Например, у `stderr`.

Поэтому при пайпинге твоя программа может «зависать» — кажется что нет вывода, а на самом деле он лежит в буфере. Решения:

```python
print('progress', flush=True)  # принудительно сбросить
```

или запустить Python в анбуферизованном режиме:

```bash
python -u script.py
```

или через переменную окружения `PYTHONUNBUFFERED=1`. На Railway, в Docker, в systemd — это маст-хэв, иначе логи приходят пачками с задержкой.

📌 *6. Эскейп-последовательности — все, которые есть*

В строковых литералах `\` начинает специальную последовательность. Самые известные:

| Escape | Что делает |
|--------|------------|
| `\n` | перевод строки (LF, U+000A) |
| `\r` | возврат каретки (CR, U+000D) |
| `\t` | табуляция (U+0009) |
| `\\` | сам обратный слэш |
| `\'` | одинарная кавычка внутри одинарных |
| `\"` | двойная кавычка внутри двойных |
| `\b` | backspace (U+0008) |
| `\f` | form feed (U+000C) |
| `\v` | vertical tab (U+000B) |
| `\a` | звонок (U+0007) — на старых терминалах пищит |
| `\0` | null (U+0000) |
| `\xHH` | символ по hex-коду (1 байт): `\x41` = `A` |
| `\ooo` | символ по восьмеричному коду |
| `\uHHHH` | Unicode-символ (4 hex): `\u00e9` = `é` |
| `\UHHHHHHHH` | Unicode-символ (8 hex) — для эмодзи и редких знаков |
| `\N{name}` | Unicode по имени: `\N{GREEK SMALL LETTER ALPHA}` = α |

Примеры:

```python
print('a\tb\tc')         # a    b    c
print('строка1\nстрока2') # на двух строках
print('Путь: C:\\\\Users') # Путь: C:\\Users
print('\u2603')          # ☃ — снеговик
print('\N{HEAVY CHECK MARK}')  # ✔
```

⚠️ `\r` — отдельная штука. Это «возврат каретки», курсор прыгает в начало строки, но *без* перевода. Очень удобно для прогресс-индикаторов:

```python
import time
for i in range(101):
    print(f'\rЗагрузка: {i}%', end='', flush=True)
    time.sleep(0.02)
print()  # перевод строки в конце
```

📌 *7. Сырые строки — `r"..."`*

Если поставить `r` перед строкой, обратный слэш становится обычным символом:

```python
print(r'C:\Users\name\file.txt')   # C:\Users\name\file.txt
print('C:\Users\name\file.txt')    # C:\Users\name\\file.txt  ← баг!
                                    # на самом деле \U в обычной строке
                                    # → SyntaxError или странный вывод
```

Это критично для:
- *путей Windows* (`r'C:\code'`),
- *регулярных выражений* (`re.compile(r'\d+')`),
- *длинных escape-сложных строк*.

Raw — это синтаксис литерала, во время исполнения уже обычная строка.

📌 *8. Кодировки и Unicode*

В Python 3 строки `str` — это последовательности *Unicode code points*, а не байтов. Когда ты делаешь `print('Привет')`, происходит:

1. У строки есть code points: `[П=1055, р=1088, и=1080, в=1074, е=1077, т=1090]`.
2. `print` пишет в `sys.stdout`, у которого есть атрибут `.encoding`.
3. Python кодирует строку в байты по этой кодировке.
4. Байты уходят в ОС.

```python
import sys
print(sys.stdout.encoding)   # 'utf-8' на Linux/Mac, 'cp1251' или 'cp866' на старых Windows
```

Если терминал не поддерживает символ, получишь `UnicodeEncodeError`. Это типичная боль на Windows для кириллицы или эмодзи.

📍 Решение для Windows: `chcp 65001` в cmd, или установка переменной:

```bash
PYTHONIOENCODING=utf-8
```

или (в коде):

```python
import sys
sys.stdout.reconfigure(encoding='utf-8')
```

📍 Эмодзи. Большинство эмодзи находятся за пределами BMP (U+10000+), поэтому занимают пары `\U00010000`+. Современные терминалы их рисуют, старые — показывают `?` или прямоугольники.

📌 *9. `print` vs `sys.stdout.write`*

`print` — удобная обёртка над `.write`. Она:
- преобразует каждый объект через `str()`,
- объединяет через `sep`,
- добавляет `end`,
- поддерживает `flush`.

`sys.stdout.write` — низкоуровневый метод. Принимает *только строку*, ничего не добавляет, ничего не преобразует.

```python
import sys
sys.stdout.write('Hello')        # OK
sys.stdout.write(42)             # TypeError: write() argument must be str
sys.stdout.write('a')
sys.stdout.write('b')
# ab — без перевода строки между ними
```

Когда `write` лучше:
- *максимальный контроль* над выводом (например, в высокопроизводительных циклах);
- *библиотечный код*, где хочется явно показать что мы пишем в поток.

В большинстве пользовательского кода — `print`.

📌 *10. ANSI-цвета и управление терминалом*

Большинство терминалов понимают *ANSI escape sequences* — последовательности `\033[...m` для цвета и оформления:

```python
print('\033[31mкрасный\033[0m обычный')
print('\033[1;32mжирный зелёный\033[0m')
print('\033[4;34mподчёркнутый синий\033[0m')
```

Цвета:
- `30..37` — основной цвет текста (чёрный, красный, зелёный, жёлтый, синий, мажента, циан, белый)
- `90..97` — яркий вариант
- `40..47` — фон
- `1` — жирный, `4` — подчёркнутый, `0` — сброс

⚠️ В Windows старых версий это не работает без библиотеки `colorama`:

```python
import colorama
colorama.init()
print('\033[31mкрасный\033[0m')
```

Полезно: можно очистить экран (`\033[2J`), переместить курсор (`\033[H`), и так далее. Для серьёзных TUI используют библиотеку `rich` или `curses`.

📌 *11. Типичные ошибки*

🔸 *Забыли скобки.* В Python 3 `print 'hi'` → `SyntaxError`. Это самая частая ошибка переходящих со 2-го Питона.

🔸 *`print` без вызова.* `print` без скобок — это сама функция как объект. В REPL покажет `<built-in function print>`. Не выводит ничего.

🔸 *`UnicodeEncodeError`.* На Windows: `UnicodeEncodeError: 'charmap' codec can't encode character`. Лечится `PYTHONIOENCODING=utf-8` или `sys.stdout.reconfigure(encoding='utf-8')`.

🔸 *Слиплись числа без пробела.* `print(a, b)` даёт `1 2`, а `print(a + b)` даёт `3`. Если оба числа и нужно сложить — используй `+`. Если нужно показать рядом — `,` (с `sep`).

🔸 *Неожиданная задержка вывода.* В пайпе/в Docker логи могут «застревать». Решение: `flush=True` или `python -u`.

🔸 *Концевой `\n`.* `print` всегда добавляет `\n` в конце по умолчанию. Если хочешь без — `end=''`.

🔸 *Запись в закрытый файл.* После `with open(...) as f:` поток закрывается, и `print(..., file=f)` снаружи `with` упадёт.

📌 *12. Что внутри (бонус — для тех, кто любит копать)*

`print` в CPython реализован на C — функция `builtin_print` в `Python/bltinmodule.c`. Она:

1. Парсит keyword-аргументы.
2. Для каждого объекта вызывает `PyObject_Str` (это `str(obj)` на уровне C).
3. Между ними и в конце пишет `sep` и `end` через `PyFile_WriteObject`.
4. Если `flush=True`, вызывает метод `.flush()` потока.

Если знаешь модуль `dis`, можно посмотреть байткод (это уже глубже — будет в продвинутом треке):

```python
import dis
dis.dis("print('hi')")
```
