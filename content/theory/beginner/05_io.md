# Ввод и вывод — от 0 до 100%

`print` мы уже разобрали в первой теме. `input` кажется ещё проще — «прочитал строку от пользователя». Но за `input()` тоже стоит много нюансов: что такое stdin, как работают потоки, почему `int(input())` падает на пробелах, как читать несколько чисел из одной строки, как обрабатывать EOF, как делать ввод с подсказкой по умолчанию, как читать из файлов и сетей.

Эта тема — про общение программы с внешним миром через **стандартные потоки** ввода и вывода.

---

## 1. Стандартные потоки

В любой программе на любой ОС (Windows, Linux, macOS) есть три стандартных потока:

- **stdin** (file descriptor 0) — поток для чтения. По умолчанию — клавиатура. Можно перенаправить из файла или другого процесса.
- **stdout** (fd 1) — поток для обычного вывода. По умолчанию — терминал.
- **stderr** (fd 2) — поток для ошибок и диагностики. Тоже терминал, но не смешивается с stdout при перенаправлении.

В Python они доступны как:
```python
import sys
sys.stdin    # для чтения
sys.stdout   # для записи
sys.stderr   # для записи ошибок
```

`input()` читает из `sys.stdin`. `print()` пишет в `sys.stdout`. Вот и всё.

### Перенаправление в шелле

```bash
python script.py < input.txt          # stdin берётся из файла
python script.py > output.txt         # stdout уходит в файл
python script.py 2> errors.txt        # stderr в файл
python script.py < in.txt > out.txt   # одновременно
echo "5\n10" | python script.py       # stdin от другой команды через pipe
```

Это объясняет, почему авточекеры задач (как наш) могут «ввести» данные программе — они подключают stdin к заранее подготовленной строке.

## 2. Базовый input()

```python
name = input()
print(f"Hello, {name}!")
```

`input()`:
1. Если есть аргумент — печатает его как «приглашение» (prompt).
2. Ждёт пока пользователь введёт строку и нажмёт Enter.
3. Возвращает введённую строку **без** завершающего `\n`.

```python
name = input("Введи имя: ")
# в терминале: Введи имя: |  (курсор)
# пользователь печатает Alice и Enter
# name = "Alice"
```

**Важно:** `input()` всегда возвращает `str`. Даже если пользователь ввёл `42` — это будет строка `"42"`, не число.

```python
n = input("Число: ")
print(n + 1)        # TypeError: can only concatenate str to str
print(int(n) + 1)   # 43 — нужен явный int()
```

### Ввод чисел

```python
age = int(input("Возраст: "))            # int
height = float(input("Рост в м: "))      # float
```

Если пользователь введёт «двадцать» — `ValueError: invalid literal for int()`. Обработать:
```python
try:
    age = int(input("Возраст: "))
except ValueError:
    print("Это не число!")
    age = 0
```

## 3. Ввод нескольких значений

### Способ 1: несколько вызовов input

```python
a = int(input())
b = int(input())
# каждое значение — на отдельной строке
```

Простой, но требует от пользователя нажимать Enter после каждого числа.

### Способ 2: split() в одной строке

```python
a, b = map(int, input().split())
# вход: "5 10"
# split() разбивает по пробелам → ["5", "10"]
# map(int, ...) применяет int к каждому → 5, 10
# распаковываем в a, b
```

Это **классика конкурсного программирования** и наш стандартный приём в задачах.

### Способ 3: сколько угодно чисел

```python
nums = list(map(int, input().split()))
# вход: "1 2 3 4 5"
# nums = [1, 2, 3, 4, 5]
```

### Способ 4: с разделителем не пробел

```python
parts = input().split(",")
# вход: "Alice,30,Moscow"
# parts = ["Alice", "30", "Moscow"]
```

### Способ 5: разные типы в одной строке

```python
parts = input().split()
name = parts[0]
age = int(parts[1])
height = float(parts[2])

# или сразу:
name, age, height = input().split()
age = int(age)
height = float(height)
```

## 4. Чтение нескольких строк

```python
n = int(input())
lines = [input() for _ in range(n)]
```

Сначала читаем число строк, потом столько же строк подряд.

```python
n = int(input())
data = []
for _ in range(n):
    a, b = map(int, input().split())
    data.append((a, b))
```

Или если **неизвестно сколько** — читать до EOF (см. секцию 8).

## 5. input() и пробелы

`input()` берёт **всё до Enter**. Если пользователь ввёл `  hello  ` — вернётся `"  hello  "` с пробелами.

```python
s = input("Введи: ")
# вход: "  hello  "
print(repr(s))    # '  hello  '
```

Для чистого ввода — `.strip()`:
```python
s = input().strip()
```

И `split()` уже сам игнорирует пробелы, так что для парсинга не критично.

## 6. Вывод и буферизация

`print` мы разбирали — добавлю про буферизацию, которая часто кусает на проде:

### Что такое буферизация

`print` не пишет каждый раз в терминал/файл сразу. Сначала набирается **буфер** (4-8 КБ), потом разом сбрасывается. Это сильно ускоряет, потому что системные вызовы дорогие.

В трёх режимах:
- **Line-buffered**: сброс при каждом `\n`. По умолчанию для интерактивного терминала.
- **Block-buffered**: сброс когда буфер полон. По умолчанию для файлов и pipe.
- **Unbuffered**: сразу пишется. По умолчанию для stderr.

### Когда это кусает

```python
# script.py
import time
print("Start")
time.sleep(10)
print("End")
```

Запускаешь `python script.py | tee log.txt` — и в течение 10 секунд **ничего не видно**, потому что stdout перенаправлен в pipe → block-buffered → буфер ещё не полон.

Лекарства:
- `print("...", flush=True)` — принудительный сброс.
- Запустить Python с `-u` (unbuffered): `python -u script.py`.
- Установить переменную: `PYTHONUNBUFFERED=1`.
- Прямо в коде: `sys.stdout.reconfigure(line_buffering=True)` (Python 3.7+).

В Docker и Railway это особенно важно — чтобы видеть логи в реальном времени, обычно ставят `PYTHONUNBUFFERED=1`.

### print vs sys.stdout.write

```python
print("hello")             # автоматом добавляет \n
sys.stdout.write("hello")  # без \n, без флаша
sys.stdout.write("hello\n")
sys.stdout.flush()
```

`print` — удобнее. `sys.stdout.write` — быстрее в горячем цикле, но в реальной жизни эта разница пренебрежимо мала.

## 7. stderr — для ошибок

```python
import sys
print("Это нормальный вывод")
print("Это ошибка", file=sys.stderr)
```

Зачем разделение? Чтобы можно было:
- логировать ошибки в один файл (`2> errors.log`), а вывод в другой (`> data.txt`);
- видеть ошибки на экране, даже когда вывод в pipe;
- инструменты (Docker, systemd) собирают stderr отдельно.

Логи всегда лучше идут в stderr (или через модуль `logging`, который тоже по умолчанию в stderr).

## 8. Чтение до конца файла (EOF)

Если не знаешь сколько строк будет — читай в цикле до **EOF** (End Of File).

### Способ 1: try/except EOFError

```python
nums = []
while True:
    try:
        nums.append(int(input()))
    except EOFError:
        break
```

В терминале EOF подаётся клавишами **Ctrl+D** (Linux/macOS) или **Ctrl+Z, Enter** (Windows). При перенаправлении из файла — естественно после последней строки.

### Способ 2: sys.stdin построчно

```python
import sys
for line in sys.stdin:
    line = line.rstrip()    # без \n
    process(line)
```

Это идиоматично — итерация по `sys.stdin` останавливается на EOF сама.

### Способ 3: всё разом

```python
import sys
data = sys.stdin.read()    # вся строка целиком
lines = data.splitlines()
```

Удобно для коротких задач, неэффективно для огромных файлов.

## 9. Чтение из файлов

### Базовый паттерн

```python
with open("data.txt", "r", encoding="utf-8") as f:
    contents = f.read()              # всё содержимое
    # или
    for line in f:
        process(line.rstrip())       # построчно — лучше для больших файлов
```

`with` — это **контекстный менеджер**, гарантирует закрытие файла даже при исключении. Подробно в теме «Файлы и JSON». Без `with` пришлось бы:
```python
f = open("data.txt", "r", encoding="utf-8")
try:
    contents = f.read()
finally:
    f.close()
```

### Режимы открытия

| Режим | Что делает |
|---|---|
| `"r"` | чтение (по умолчанию) |
| `"w"` | запись — **перезаписывает** файл |
| `"a"` | дописывание в конец |
| `"x"` | создание — падает если уже существует |
| `"b"` | двоичный (вместе с другими: `"rb"`, `"wb"`) |
| `"+"` | чтение и запись (`"r+"`, `"w+"`) |

```python
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("Hello\n")
    f.write("World\n")
    print("Тоже работает", file=f)    # print тоже принимает file
```

### Кодировки

Всегда указывай `encoding`. По умолчанию — locale-зависимо, что значит «на Windows может оказаться cp1251 и всё сломается».

```python
with open("file.txt", "r", encoding="utf-8") as f:
    ...
```

Стандарт — UTF-8 везде.

### Двоичный режим — для не-текстовых файлов

```python
with open("image.png", "rb") as f:
    data = f.read()    # bytes, не str

with open("output.bin", "wb") as f:
    f.write(b"\x00\x01\x02")
```

В двоичном режиме `encoding` запрещён — там нет «текста», только байты.

## 10. Запись через print в файл

```python
with open("log.txt", "w", encoding="utf-8") as f:
    print("Запись 1", file=f)
    print("Запись 2", file=f)
```

То же самое что `f.write("Запись 1\n")`, но удобнее — print сам добавляет `\n` и форматирует.

`print` принимает все свои обычные аргументы (`sep`, `end`, `flush`):
```python
print("a", "b", "c", sep=" | ", end="!\n", file=f)
# в файл: "a | b | c!"
```

## 11. pathlib — современный способ работать с путями

Вместо строковых путей и `os.path` — модуль `pathlib`:

```python
from pathlib import Path

p = Path("data") / "file.txt"
print(p)              # data/file.txt (или data\file.txt на Windows)
print(p.exists())
print(p.parent)       # data
print(p.suffix)       # .txt
print(p.stem)         # file

# чтение/запись
text = p.read_text(encoding="utf-8")
p.write_text("hello", encoding="utf-8")
data = p.read_bytes()
p.write_bytes(b"\x00")
```

`pathlib` понимает разделители путей в обеих ОС, не требует дублировать слеши, имеет удобные методы (`glob`, `iterdir`, `mkdir`).

## 12. Цветной и форматированный вывод

ANSI escape-последовательности (см. тему 1) дают цвета:

```python
RED = "\033[31m"
GREEN = "\033[32m"
RESET = "\033[0m"
print(f"{RED}Ошибка{RESET}: что-то сломалось")
```

В Windows старые версии терминала не поддерживают, в Windows 10+ — работает. Для надёжности — пакет `colorama`:
```python
from colorama import init, Fore
init()
print(Fore.RED + "Ошибка" + Fore.RESET)
```

Для красивых таблиц/прогресс-баров — `rich`:
```python
from rich import print
from rich.console import Console
console = Console()
console.print("[bold red]Ошибка[/]: подробности")
```

`rich` — одна из лучших библиотек для CLI. Стоит попробовать.

## 13. Тонкости input()

### Echo (отображение ввода)

`input()` показывает введённое (echo). Для скрытого ввода (паролей) — модуль `getpass`:
```python
from getpass import getpass
password = getpass("Пароль: ")    # ввод не отображается
```

### Прерывание (Ctrl+C)

`input()` ждёт ввода. Если пользователь нажмёт Ctrl+C — вылетит `KeyboardInterrupt`. Часто хочется обработать вежливо:
```python
try:
    name = input("Имя: ")
except KeyboardInterrupt:
    print("\nОтменено")
    sys.exit(0)
```

### Empty input

Если пользователь нажал Enter без ввода — `input()` вернёт пустую строку `""`, а не None.

```python
s = input()
if not s:
    print("Пустой ввод")
```

### Несколько строк на один input

В терминале **нельзя** в одном `input()` ввести несколько строк (Enter завершает ввод). Если нужно — читай несколько раз или из файла.

## 14. Команды-помощники для ввода

### sys.argv — аргументы командной строки

```python
import sys
print(sys.argv)         # ['script.py', 'arg1', 'arg2']
print(sys.argv[1])      # 'arg1'
```

Запуск: `python script.py arg1 arg2`. Часто это удобнее интерактивного `input()`.

### argparse — для серьёзных CLI

```python
import argparse
parser = argparse.ArgumentParser()
parser.add_argument("--name", required=True)
parser.add_argument("--count", type=int, default=1)
args = parser.parse_args()

print(f"Hello {args.name} x{args.count}")
```

Запуск: `python script.py --name Alice --count 3`. Есть валидация, помощь по `--help`, типы. Для любых CLI-программ — must-have.

### Переменные окружения

```python
import os
api_key = os.environ.get("API_KEY")
debug = os.environ.get("DEBUG", "0") == "1"
```

Используется для конфигурации, особенно в Docker/Railway/Kubernetes.

## 15. Логирование вместо print

Для серьёзных программ вместо `print` используй `logging`:

```python
import logging
logging.basicConfig(level=logging.INFO)
log = logging.getLogger(__name__)

log.info("Started")
log.warning("Малое количество памяти")
log.error("Сломалось!")
```

Преимущества:
- разные уровни (DEBUG, INFO, WARNING, ERROR, CRITICAL);
- можно отключить debug в продакшене одной строкой;
- автоматически добавляет timestamp, имя модуля;
- может писать в файл, в stderr, в систему сбора логов одновременно.

`print` — для CLI и быстрых скриптов. `logging` — для приложений.

## 16. Типичные ошибки

**`ValueError: invalid literal for int()`** — пользователь ввёл не число. Оборачивай `int(input())` в try/except.

**Не вижу логов в Docker / pipe / Railway** — проблема буферизации. Установи `PYTHONUNBUFFERED=1` или используй `flush=True`.

**Файл не закрывается** — забыл `with`. Используй контекстный менеджер всегда.

**UnicodeDecodeError при чтении файла** — не указал `encoding="utf-8"`. На Windows может попасть в cp1251.

**input() в скрипте, который запускается из задания** — оно читает не от пользователя, а из stdin (который может быть перенаправлен из файла). Логика та же, но на терминале нет приглашения.

**`int(input())` для чисел через пробел** — `int("5 10")` падает. Нужен `split()`:
```python
a = int(input().split()[0])    # просто первое число
```

**EOFError неожиданно** — `input()` в скрипте дочитал до конца stdin. Используй try/except или цикл по `sys.stdin`.

**`print` с file=stderr — забыл flush** — stderr в Python unbuffered, но при перенаправлении может зашифроваться. Если важно — `flush=True`.

## 17. Что нужно запомнить

- `input()` всегда возвращает `str`, конвертируй явно (`int`, `float`).
- Для нескольких чисел в одной строке: `map(int, input().split())`.
- Для нескольких строк: цикл с `range(n)` или `for line in sys.stdin`.
- EOF: `try/except EOFError` или итерация по stdin.
- Файлы — всегда с `with` и явным `encoding="utf-8"`.
- Буферизация: для real-time логов `flush=True` или `PYTHONUNBUFFERED=1`.
- stdout — для данных, stderr — для ошибок и логов.
- `pathlib.Path` лучше, чем `os.path` + строки.
- Для production-программ — `logging`, не `print`.

После этой темы ты можешь писать программы, которые **общаются** с пользователем и файлами. Дальше — условия и циклы, где будем использовать ввод во всех конструкциях.
